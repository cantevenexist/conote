# Conote
## Этот проект представляет собой веб-сервис, в котором серверная часть реализована с использованием фреймворка Django, клиентская часть — на JavaScript, HTML и CSS. В качестве системы управления базами данных используется PostgreSQL. Основной функционал системы заключается в создании виртуальных досок, на которых можно размещать канбан-доски с возможностью добавления участников и синхронизации в реальном времени с помощью WebSocket и Django Channels (в связке с Valkey). Для обработки фоновых и асинхронных задач используется Celery с брокером сообщений RabbitMQ. Все файлы хранятся во внешнем объектном хранилище MinIO. Все компоненты приложения — включая сервер, БД, брокеры и хранилище — развернуты в Docker-контейнерах, что обеспечивает удобную оркестрацию и переносимость. В рамках проекта были реализованы шаблоны досок с предустановленными колонками и карточками, адаптированными под специалистов в области информационной безопасности.

### Архитектура веб-сервиса.
Архитектура разработанного приложения представлена на рисунке 1, которая иллюстрирует взаимодействие всех ключевых компонентов системы, обеспечивающих функционирование сайта для автоматизации реагирования на инциденты информационной безопасности. Система позволяет пользователям создавать виртуальные доски, добавлять участников и синхронизировать изменения в реальном времени.

Приложение включает следующие ключевые элементы:
1) Клиентская часть: реализована с использованием технологий JavaScript, HTML и CSS. Обеспечивает пользовательский интерфейс для создания и управления виртуальными досками, а также взаимодействия между участниками.
2) Серверная часть: построена на основе библиотеки Django, функционирующей на языке Python. Отвечает за обработку запросов, управление логикой приложения и координацию работы с другими сервисами.
3) Синхронизация в реальном времени: осуществляется с применением протокола WebSocket и библиотеки Django-Channels. Гарантирует мгновенное обновление данных на всех подключённых клиентах при внесении изменений.
4) База данных: используется объектно-реляционная СУБД PostgreSQL для хранения структурированных данных, включая информацию о пользователях, метаданные досок и ссылки на файлы в объектном хранилище.
5) Объектное хранилище: применяется MinIO, совместимое с S3, для хранения JSON-файлов, содержащих содержимое виртуальных досок, а также для хранения всех медиа-файлов.
6) Хранение команд: Valkey используется для временного хранения команд, отправляемых пользователями при взаимодействии с доской. Команды сохраняются в списках Valkey (Valkey Lists).
7) Асинхронная обработка задач: Celery в сочетании с брокером сообщений RabbitMQ применяется для выполнения фоновых задач, таких как генерация обновлённых JSON-файлов при накоплении команд.
8) Контейнеризация: все компоненты развёрнуты в контейнерах Docker, что обеспечивает изоляцию, согласованность окружений и упрощённое управление.

Процесс взаимодействия между компонентами можно описать следующим образом:
1) Действие пользователя: пользователь через клиентский интерфейс выполняет действие на виртуальной доске, например, добавляет карточку на доску.
2) Передача команды: клиентское приложение отправляет команду, описывающую это действие, на сервер по протоколу WebSocket.
3) Обработка и рассылка: сервер, используя Django-Channels, принимает команду, рассылает её всем подключённым клиентам, работающим с той же доской, и сохраняет команду в списке Valkey, соответствующем данной доске.
4) Загрузка доски: при входе пользователя на доску клиент запрашивает текущий JSON-файл с сервера. Сервер извлекает файл из MinIO и передаёт его клиенту вместе со списком всех команд, находящихся в Valkey для этой доски. Клиент получает файл, представляющий базовое состояние доски, и список команд, отражающих изменения с момента последнего обновления файла. Применяя команды к базовому состоянию, клиент воссоздаёт текущее состояние доски.
5) Обновления в реальном времени: после загрузки клиент устанавливает соединение WebSocket и получает новые команды по мере их поступления, обновляя состояние доски в реальном времени.
6) Консолидация данных: когда количество команд в списке Valkey превышает 100, запускается задача Celery. Эта задача извлекает текущий JSON-файл из MinIO, применяет к нему все накопленные команды, формирует новый JSON-файл с обновлённым состоянием и сохраняет его. После этого список Valkey очищается.
